# Shell 输入/输出重定向与文件描述符

Linux 哲学中“一切皆文件”。每个进程启动时，默认打开三个标准文件描述符（File Descriptors）：
- **`0` (STDIN)**：标准输入，默认来自键盘。
- **`1` (STDOUT)**：标准输出，默认输出到终端屏幕。
- **`2` (STDERR)**：标准错误输出，默认输出到终端屏幕。

---

## 1. 核心重定向操作符速查表

| 操作符 | 说明 | 示例 |
| :---: | :--- | :--- |
| **`>`** 或 **`1>`** | 标准输出覆盖写入文件 | `echo "ok" > status.txt` |
| **`>>`** | 标准输出追加写入文件 | `echo "log" >> app.log` |
| **`<`** | 标准输入重定向自文件 | `wc -l < users.txt` |
| **`2>`** | 标准错误覆盖写入文件 | `ls /not_exist 2> err.log` |
| **`2>>`** | 标准错误追加写入文件 | `python train.py 2>> err.log` |
| **`2>&1`** | 将标准错误合并重定向到标准输出 | `command > app.log 2>&1` |
| **`&>`** | 标准输出与错误全部重定向 (Bash 简写) | `command &> app.log` |
| **`<< EOF`** | Here Document（多行文本块输入） | `cat << EOF > config.env` |

## 2. 生产实战高频用法

### 2.1 静音执行 / 屏蔽所有输出 (`/dev/null`)
`/dev/null` 是 Linux 的黑洞设备，写入的所有内容都会被立即丢弃：

```bash
# 1. 经典兼容写法 (标准输出和标准错误全部丢弃)
nohup python app.py > /dev/null 2>&1 &

# 2. Bash 现代简写
python app.py &> /dev/null &

# 3. 仅丢弃错误信息，正常结果保留
find / -name "nginx.conf" 2> /dev/null
```

### 2.2 同时输出到屏幕并保存到文件 (`tee`)
重定向符号 `>` 会截断屏幕输出。若希望既在终端看到日志，又保存到文件，使用 `tee`：

```bash
# 覆盖写入
./build.sh | tee build.log

# 追加写入 (-a)
./test.sh | tee -a test.log

# 同时将标准错误和输出一起展示并记录
./start.sh 2>&1 | tee -a run.log
```

## 3. Here Document 生成配置文件

使用 `cat << 'EOF' > file` 可以极其优雅地在 Shell 中生成多行配置文件：

```bash
#!/bin/bash

APP_PORT=9000
ENV="production"

# 1. 变量解析模式 (EOF 不加引号，内部 $APP_PORT 会被替换)
cat << EOF > server.conf
[server]
port = ${APP_PORT}
env = ${ENV}
EOF

# 2. 原样输出模式 (给 'EOF' 加上引号，内部所有 $ 符号原样输出，常用于生成脚本)
cat << 'EOF' > script.sh
#!/bin/bash
echo "Current PID is: $$"
EOF
```
